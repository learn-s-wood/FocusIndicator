# 设计说明

写给改这个库的人。用法和行为在 README，这里只记"为什么这么做"。

## 脏区重绘

两个绘制层是独立 View，各自只 invalidate 自己的一小块脏区，动画期间不会让业务子 View
重新走 dispatchDraw，重绘面积通常只有全屏的几十分之一。这是 API 17 老盒子也能满帧的原因。

标脏用的是"上一帧 ∪ 当前帧"的外接矩形。不能裁到 View 自己范围内：跨容器接力时起始外形
可能落在容器外（比如从上一行飞下来，起始 Y 为负），裁掉的话那块旧像素不会重绘，飞行会变成
从容器边缘"长出来"。

## 外形测量

`measureRect` 用 `getLocationInWindow` 相减算 item 在本容器的外形，嵌套滚动、任意层级都成立。

坑在缩放：`getLocationInWindow` 内部会应用 item 自己的 matrix（`getMatrix().mapPoints`），
item 缩放后返回的已经是绕 pivot 外扩之后的左上角，translationX/Y 也算进去了。所以只能拿它当
视觉左上角，配上"宽高 × scale"直接拼矩形，不能再按"layout 左上角 + 宽/2 是中心"去算。后者会把
matrix 已折算过的外扩再加一遍，框整体往左上偏 `(scale - 1) * 尺寸 / 2`，缩放越大偏得越多。
这样写对非中心 pivot 也成立，前提是父级容器自身不做缩放。

## 跨容器接力（Group）

单个容器只看得到自己子树里的焦点。焦点跨容器时先隐藏、再在新容器出现，中间会闪一下。把同页
多个容器绑到同一个 Group，隐藏前的外形按窗口坐标记下来，新容器接手时换算回自己的坐标系当
动画起点，视觉上就是一框飞过整页。

隐藏是同步发生的，跟随是 post 出去的，所以容器之间的回调先后顺序不影响接力。一个页面一个
实例，随 Activity 回收，不用手动清。

接力点写两处：Group 里一份窗口坐标，容器自己一份局部坐标。没设 Group 时，单容器也能有移动动画。

代码方式（`ignoreFocus` / `unignoreFocus`）用 `WeakHashMap` 存 View，列表回收时不用手动清。

## 豁免项的进出场

`fi:ignore` 命中后容器不画，但位置还是要记。容器和接力组存的是"上一次隐藏的位置"，如果进入
豁免项时直接隐藏，留下的还是更早那个普通 item 的坐标。`大卡片 → 英语（豁免）→ 儿歌` 这种
走法，从英语离开时框就会从大卡片飞过来。

同容器内：框滑向豁免项，路上淡完。跨容器时：出发容器原地退场，把接力点记成豁免项的位置就够了。
常规跨容器本来就靠接力组交接，豁免项又没有自己的框，再派一个框飞过去是多余的一段动作；
也不让目标容器临时显示自己的层，免得从没有底色的 item 过来时凭空冒出一块色。

淡出停在路程 2/3 附近，框在碰到豁免项之前就没了，不和它自己那套焦点态叠（叠上去像双击）。
这个点绑的是路程不是时间，`setDuration()` 调长也不会退化成"贴到才消失"。

这一段位移单独用 `AccelerateDecelerateInterpolator`。常规的 `DecelerateInterpolator(1.8f)`
公式是 `1-(1-t)^3.6`，时间走到 26% 时路程已经过了 2/3，用它的话"淡尽在路程 2/3"只剩约 57ms
可见，看着就是闪一下。换成更均匀的曲线后停在同一个路程上，可见时间约 134ms。

注意：改这段曲线或时长时，`HIDE_FLY_FADE_TIME_RATIO` 要按换算公式重算。AccelerateDecelerate 下
路程 p 对应时间 `acos(1-2p)/π`，p = 2/3 时是 0.61。

## 接力点的写入时机

飞行途中 `currentRect` 是插值出来的中间点，不是真实目标。所以接力点在起飞前就按目标位置写好，
并用 `flyingToIgnored` 标记；飞行被打断（焦点跳到别处）时，`hideIndicator()` 不能再拿中间点
覆盖它。

## 光晕

不用 `setShadowLayer` / `BlurMaskFilter`：API 19 的老机器上它们会退化成软件绘制。

1.0.0 用两层半透明实心矩形叠，item 内部被一起染色（网格场景只开描边 + 发光时看着像被填了色），
改成 `STROKE` 环后光晕只在边框外圈。但两环在贴边那段重叠，内侧一档混合出来是 52% 而不是
配置的 40%，看着是"几层图叠起来的硬边"。

现在把总厚度 `2 × width` 切成 `layers` 个互不重叠的同心环（默认 6），第 i 环覆盖
`[i·band, (i+1)·band]`，alpha 按环中心距离线性衰减到接近 0。多一档就多一次 drawRoundRect，
所以 `layers` 暴露成参数，API 19 的盒子嫌慢就传小一点。

paint 的颜色、描边、`strokeJoin`、环宽都在 `setStyle()` 时定好，`onDraw` 每帧只逐环改 alpha。

## 圆角自动跟随

没配 `corner()` 时读目标 View 自己的圆角：API 24+ 问 `Outline`（`getRadius()` 24 才公开），17~23 反射 `GradientDrawable`
内部状态（外面包了 `RippleDrawable` / `LayerDrawable` 就往下找一层）。读到后要叠上外扩量，
圆角矩形外移 `p` 后圆角是 `r + p`。

结果按"目标 View + 背景引用"缓存，逐帧贴合不会重复反射。注意 selector 在 state 之间换 shape
不会重读（缓存只认背景引用），这类 item 得显式 `corner()`。读不到就按直角画，不报错。

## 淡入淡出

用 `Paint.alpha` 而不是 `View.alpha`：隐藏期间仍然只脏区重绘，不会让整块浮层全量重绘。

"开关"设计成时长而不是布尔值：`setFadeDuration(in, out)`，传 0 就是硬切，两个方向独立。
`fadeIn()` / `fadeOut()` 每次触发都读当前字段，所以运行时可随时改。

## 框与列表同时动

列表要把焦点项滚到中间时，框钉在原地等列表滚完再补飞一段，观感上就是两步动作。
做法是先算出焦点项居中后会落在哪，再让框直接飞到那个位置，列表同时滚过去。

落点只能算，不能看。滚动途中的瞬时位置拿来判断会得出相反的结论：滚得越快偏得越多，
慢按和快按的结果不一样。要算的是"焦点项居中后相对当前位置平移多少"，这个量只跟内容
布局和内容范围有关，跟滚到哪一帧无关。

位移要按内容范围钳制。列表到头时焦点项居中不了（往回滚不动），偏移量就是 0，框落在
焦点项当前位置。不钳制的话框会飞到焦点项根本没到过的地方，框和 item 就分家了。

框飞向固定落点后位置不能再跟目标走，但尺寸要跟。`followToOffset` 记下落点中心：
飞行途中和贴合阶段都只重采目标的实时宽高，中心留在落点上。目标 View 仍然留着，
圆角跟随靠它。

这样"焦点不动、列表动"和"目标 item 尺寸不一样"能同时成立：框停在落点上，宽高跟着
新目标变。

补居中是另一条路：预测落点和实际对不上时，把框放回焦点项上，滚动期间框跟着焦点项走，
滚完再核对一次。这条路要封顶，不然会绕圈。

## 测量

自定义 `onMeasure` 要和原生 `FrameLayout` 一致：跳过 `GONE` 子 View（否则 `MATCH_PARENT` 的
隐藏子 View 会把 `wrap_content` 容器撑满），并保留 `android:foreground`、
`android:minWidth` / `android:minHeight`。
